# Kimodo Unity 6000.5.7f1 单剪辑工作流验证报告

## 结论

本次仅使用 Unity `6000.5.7f1 (017862109af0)`，在全新隔离项目中从本工作树以本地 UPM 包安装开始，真实调用 `KimodoUnityBridge.Command.command_dispatcher`。当前公开的 18 个 API 均取得了 Unity 6000.5 进程内响应；除具有删除语义的 `session_try_remove` 只验证了安全错误返回外，其余 API 都取得至少一个成功基本响应，并为安全 API 保存了代表性错误响应。

唯一一次 AI 单剪辑生成请求已从 `running` 轮询到终态 `completed`，随后确认生成 AnimationClip、执行 Analysis、生成四视图图片并完成独立 Bake。没有修改产品代码，没有调用多剪辑生成 API，没有新增 Hand/Foot IK Command，没有测试其他 Unity/Tuanjie 版本，也没有 push。

分类含义：

- `实际 Unity 6000.5 运行时验证`：在目标 Unity 进程中实际调用，并观察到返回、Session/文件/图片/终态等效果。
- `仅 schema/返回值验证`：调用成功，但只证明发现或返回契约，不证明场景副作用。
- `未验证`：为遵守非破坏、单剪辑或成本边界而未执行的成功分支。

## 发现顺序与当前契约

验证驱动最先记录：

1. `command_dispatcher.GetCommandDefinitionsJson()`：返回 18 个工具。
2. `command_dispatcher.Invoke("kimodo_help", "{}")`：返回当前基础工作流 `session_open -> query_current_session -> kimodo_generate_animation -> kimodo_get_generation -> session_close`。
3. 对 18 个工具逐一调用 `kimodo_help({"command":"..."})` 并保存实时 schema。
4. 安装 QuickServer 后调用 `kimodo_help({"section":"models"})`：返回 22 个配置；默认配置为 `Kimodo-SOMA-RP-v1 / high_performance`，CUDA/NF4，可用。

`Manual/Command API 说明书.md` 当前指向包根目录 `SKILL.md`/`SKILL-zh.md`，但本提交工作树中这两个文件不存在。这是文档入口缺口；本次没有猜测旧参数，执行依据是实时 schema 与现有 `Manual/AI 工作流示例与 Constraint API 设计.md`。

## 单剪辑工作流

角色使用包内 `Packages/com.unity.kimodo_unity_motion_tools/Editor/Model/T-Pose.fbx` 实例化为 `Unity65VerifyHumanoid`。Unity 实际报告 Avatar `present:true, valid:true, human:true`。

主要生成参数：

```json
{
  "character": "Unity65VerifyHumanoid",
  "prompt": "stand still and breathe naturally",
  "duration_frames": 60,
  "seed": 650507,
  "output_mode": "humanoid_muscle",
  "output_folder": "Assets/KimodoVerificationGenerated",
  "name": "Unity65_SingleClip",
  "constraints": [
    {
      "frame": 0,
      "type": "fullbody",
      "pose": {"source": "Unity65VerifyHumanoid.Poses", "frame": 0}
    },
    {
      "frame": 59,
      "type": "root2d",
      "position": [0.5, 0.0],
      "heading": [1.0, 0.0]
    }
  ]
}
```

请求接受响应为 `request_id: 8672331c-466b-4b1c-bbd1-0806cb4d8a3c`、`status: running`，模型 `Kimodo-SOMA-RP-v1`、编码器 `high_performance`。验证驱动每 2 秒调用 `kimodo_get_generation`；首次项目安装期间下载 4.3 GiB NF4 文本编码器，最终响应为：

```json
{
  "request_id": "8672331c-466b-4b1c-bbd1-0806cb4d8a3c",
  "status": "completed",
  "stage": "Completed",
  "message": "Generation complete.",
  "error": "",
  "seed": 650507,
  "animation": "Unity65_SingleClip",
  "duration_frames": 60,
  "ok": true
}
```

从请求启动到终态约 178 秒，包含首次模型下载和加载。终态后再次查询仍为 `completed`；调用取消 API 返回 `canceled:false`，确认没有把已完成任务改为取消。

Session 查询确认生成动画 `source:"generated"`、起始帧 0、时长 60；`animation_constraints` 返回 frame 0 的 FullBody 与 frame 59 的 Root2D。生成文件 `Kimodo_Unity65_SingleClip.anim` 为 1,148,694 字节、43,861 行，包含非空 Muscle float curves。独立 Bake 生成 `Kimodo_Unity65_BakeProbe.anim`，202,779 字节。

Analysis 成功返回 `analysis_id: b845ad02-10c4-4b87-af51-ca97c75520e8`，关键帧映射到 Session frame 0、34、58。两张 256×256 四视图图片均已实际写出并人工查看：角色可见，Analysis 图包含三个不同帧姿势；这不等价于交互式 Timeline 播放验证。

## 代表性错误汇总

已保存的安全错误包括：畸形 JSON、非法 help section、缺少 query/pose/analysis source、未知角色/Pose source/request ID、只读 Pose 写入、非法 Root2D shape、逆序 Bake 区间、Assets 外输出路径、无截图源、重复关闭 Session。没有为错误覆盖重复触发生成，也没有执行删除或清理命令。
