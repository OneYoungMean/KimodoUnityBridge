# 通用执行约定

[English](common.md)

本文是 [common.md](common.md) 的中文版本，是根目录 Skill 当前使用的共享执行约定。它以一个循环替代原来的四阶段手册，并保留历史识别与比较流程中有用的证据规则。在同一动画任务中，Kimodo 命令和 Unity／项目 API 是地位相同的实现路径。

## 范围与任务分流

本工作流主要处理 Humanoid 动画片段（Clip）、生成用姿态（Pose），以及门、球、武器等由 Transform 驱动的简单道具。遇到 Animator Controller、状态机、游戏逻辑脚本、复杂绑定、四足角色、载具或物理制作时，检查可用的 Unity／项目 API，并通过合适路径完成可支持的部分；需要专业逐帧表演润色时再交给动画师。

根据用户期望的结果选择主要路径；存在依赖关系的子任务可以组合使用不同路径：

| 请求 | 路径 |
|---|---|
| 检查或比较现有动画 | 解析并评估现有 Clip；跳过生成和源动画编辑。 |
| 生成新动画 | 定义标准，生成候选，再进行评估。 |
| 改进、续接或重定向现有 Clip | 检查源动画，选择编辑或生成路径，并将派生产物与源动画比较。 |
| 制作角色与道具交互动画 | 协调角色动作、道具运动、接触事件和 Timeline 集成；验证组装后的完整结果。 |
| 意图不明确 | 先检查可用上下文；只对尚未解决且会实质改变结果的选择提问。 |

## 命令入口与状态

公开的 Editor 入口如下：

```csharp
string schema = KimodoUnityBridge.Command.command_dispatcher.GetCommandDefinitionsJson();
string result = KimodoUnityBridge.Command.command_dispatcher.Invoke(commandName, argumentsJson);
```

选择工具前，先规划在 Unity 中最终可见的完整结果。Kimodo 命令、Unity Editor API、Timeline API、AnimationClip／AnimationCurve API、运行时 API 和项目本地工具，都是同一执行循环中的平等路径。用户明确指定命令或工具路径时，按该路径实际调用；用户未指定时，选择能直接产出目标结果的路径。实时 schema 可用时优先读取；连接的 Editor 不可用时，以仓库 `help.json` 为起点，并根据调用返回的结构化错误调整。使用协议中的命令名，不使用内部 C# 处理函数名。通过 Unity CLI 操作时，在已连接的 Editor 中执行 dispatcher。命令帧率为 60 FPS；每个字段应按文档规定，使用 Clip 相对帧或 Timeline 全局帧作为基准。为每个子任务记录 `子任务 → 实现路径 → 产物 → 验收检查`。如果某项操作更适合使用被允许的 Unity 或项目 API 表达，就直接使用该 API，并记录所用路径。

[`Command/help.json`](../Command/help.json) 是仓库中的命令参考；实时 schema 可用时，应与之对照。

通过 `scene.context` 和相关命令返回结果解析角色、Clip、Timeline 和 Session 引用。场景对象使用返回的句柄，Pose 槽位使用 `{track,index}`，接受路径的字段使用资产路径。

当前 Unity 场景、Timeline 和 Kimodo Session 构成可编辑的工作管线。Agent 可以切换上下文，也可以通过插入轨道、Clip、绑定或同步的道具运动扩展现有 Timeline。默认保留已有轨道和 Clip；优先添加轨道或创建派生 Timeline，而不是重写或重建现有内容。只有任务确实需要时才修改现有内容，并先保留可恢复的原始版本。编辑后，在目标 Timeline 中验证当前场景／Session、轨道绑定、Clip 范围和同步关系。

需要移除内容时，将受影响文件及对应的 Unity `.meta` 文件移入就近的 archive 目录，并检查受影响的引用。

坐标空间约定：

- 公开命令中的位置和目标（`root`、`effector` 和 `pose.set`）均使用 Unity 世界空间。
- 按实时 input schema 构造 Root2D、Effector 和 FullBody 点约束。`root.rotation` 和 `effector.*.rotation` 使用度数制欧拉角 `[x,y,z]`；省略的 Transform 通道保留采样值。schema 和结构化命令错误会说明无效 Transform、缺少 root 上下文及重复帧。
- `animation.analysis.root_trajectory` 返回世界空间数据。被分析的 Clip 从第 0 帧开始，因此其轨迹零点就是该命令使用的世界空间参考点。当 `animation.generate` 使用其 `root_path` 时，生成流程会基于目标角色在世界空间中的根位置和水平朝向，对该世界空间路径做一次解析。
- 关节局部旋转和相机专用字段继续使用各自文档规定的空间；世界空间规则适用于位置和目标字段。

任务开始时，维护一份简洁的循环状态：

```text
任务路径与当前检查项
意图、明确要求、假设和未知项
项目／场景／Session、角色／对象引用及相关工具版本
规划中的 Clip 及其依赖关系
子任务与实现路径的对应计划，以及已生成的资产／轨道
验收标准与允许的动作语义备选项
已确认的 Pose、root、effector、路径和对象证据
候选记录：request_id、animation_id、seed、prompt、constraints、analysis_id
各项标准的结果：verified、failed 或 unknown
修订历史、最佳候选、尝试预算与无改进次数
各子任务的能力依据和未解决的选择
```

通过持久化的 Session 历史和返回的 ID 查找候选，让公开状态和场景／分析载荷继续由各自现有来源维护。

## 路径与检查约定

使用上面的任务分流。schema 查询和场景检查等只读探索，可以先于路径确认。生成或编辑前，明确目标对象或 Clip、预期产物、相关标准及依赖关系。默认保留原始版本并创建派生产物；直接沿用用户已有的授权，不重复询问。

对每个子任务，区分实现路径及其能力依据：

| 能力 | 所需依据 |
|---|---|
| 当前 Kimodo 命令 | 存在于实时 schema 中；还需检查当前场景和运行时前置条件。 |
| Unity 或项目 API 路径 | 检查相关 API 及其集成方式，再在当前项目中验证产物。 |
| 提议中的能力 | 先检查 package 和实时 schema，确认实现状态后再依赖该能力。 |
| 不可用路径 | 记录已检查的命令／API 路径，然后切换到可用路径或说明剩余限制。 |

schema 中存在某接口，说明接口可用；再通过验收检查确认产物是否满足任务要求。标准结果（`verified`、`failed`、`unknown`）以及是否交接给动画师，都与能力是否可用分开判断。

检查项可以重新进入；跳过与当前路径无关的工作：

| 检查项 | 执行依赖工作前所需的证据 |
|---|---|
| 意图与范围 | 用户要求的结果、明确限制、会影响结果的选择，以及无实质影响的假设。 |
| 引用与场景状态 | 目标项目／场景、角色和所需的 Avatar、源 Clip、Timeline／Session，以及相关道具的 Transform、轴心和包围盒。 |
| 约束与标准 | 已确认的坐标／帧基准、交互事件、适用容差，以及每项必要结果的可行检查方法。 |
| 执行 | 已提交的输入与 ID、最终状态或 API 产物，以及实际评估的 Timeline 绑定／范围。只检查的任务复用现有 Clip。 |
| 验证 | 与候选相匹配的测量／图像，以及必要时的播放证据；发生变化时，重新检查受影响的依赖项。 |

先通过现有上下文补齐缺失事实。尚未解决的不同选择会实质改变用户要求的结果时再提问；等待回答期间，暂停依赖该答案的生成／编辑，并继续独立工作。每项标准保持 `unknown`，直到对应证据确认结果。进入检查项本身不需要额外确认。

## 响应与异步规则

- 读取业务字段前，先检查顶层 `ok`。
- 命令错误使用 `ok=false` 和 `error={code,message,details?}`。
- 一次轮询成功时，任务 `status` 仍可能是 `failed` 或 `canceled`；应报告该最终状态及其错误。
- 保存完整、准确的 `request_id`；按固定间隔轮询，直到进入最终状态或达到限定超时。
- 这适用于所有返回待处理 `request_id` 的异步命令，包括 `server.install` 和 `animation.generate`。轮询超时意味着任务仍待处理，不代表失败或已取消；保留 ID，以便恢复查询。
- 按 `request_id` 保留并轮询运行中的请求；任务需要停止时再取消。
- 将警告和非阻断检查视为需要查看的证据。
- 保留已完成的 Clip，修订时创建派生产物。

## 从意图到标准的循环

只执行所选路径需要的工作；检查／比较任务不生成动画，也不编辑源动画：

1. 从当前场景解析参与的角色和对象。明确可见结果、动作顺序、接触点、时长和结束状态。说明假设。
2. 识别可独立检验的动作节拍；局部修订或续接确实需要独立处理时，再拆成多个 Clip。记录角色 Clip、道具运动和 Timeline 绑定之间的依赖关系。
3. 选择相关标准，区分必要约束和质量偏好。标准可以涉及语义、空间、时间、接触、结构、视觉或播放。说明可观察的检查方法和适用容差，并依据各项证据分别判断。
4. 收集所需的最少证据：`scene.context`、`pose.get`、`pose.analysis`、已有 Clip 的分析结果，或已确认的对象 Transform。当点约束预览有助于评估目标姿势时，将同一组约束传给 `pose.analysis`，查看图像、关节世界位置、目标距离和警告。设置 `combine=true` 可在一张 SceneView 图中以不透明姿势叠加显示多个预览。`pose.analysis` 与 `animation.analysis` 共用 `camera`；未显式传参时，SceneView 光照、天空盒、Gizmos 和网格沿用当前设置。若需测量生成后的姿势，使用 `pose.get` 从完成的 Clip 采样，再进行分析。
5. 当任务需要动作专用的起始 Pose 或 Clip 续接时，用 `pose.get` 解析合适来源并使用返回的 `{track,index}`。如果确实需要动作专用 Pose 且当前没有合适来源，选取或生成一段初始 Clip，物化目标帧，再通过 `pose.analysis` 检查。无需显式动作 Pose 时，可使用命令 schema 所述的 Avatar rest pose 初始化。
6. 需要生成时，根据用户明确要求和已确认的场景证据，构造简短的语义提示词和受支持的结构化约束。将用户明确给出的根位置、朝向、路径、Pose、手／脚目标、循环、时长和续接要求映射到受支持的 Kimodo 字段；使用已确认的证据补充未说明的细节，其余可选字段沿用 schema 默认值。对象曲线、Timeline 轨道、绑定及其他资产编辑使用适合的 Unity 或项目 API。检查 `pose.get` 结果并使用其返回引用作为续接来源。按依赖顺序生成 Clip，后续 Clip 使用已评估的前序结束状态。报告约束使用了显式 Pose，还是命令默认的 Avatar rest pose 初始化。
7. 只有确有需要时才生成或编辑候选，轮询异步请求，并保留 ID 和提交的设置。API 产物没有 Kimodo ID 时，保留实际资产／轨道引用。检查路径以现有产物为评估对象。
8. 先评估相关硬性要求，再按需检查结构、场景交互和播放／质量标准。使用 `animation.analysis` 评估 Humanoid Clip；使用求值后的场景测量和适当 API 检查道具／Timeline。作出视觉结论前，先打开返回图像。接受某项标准前，核对下文规定的证据与产物对应关系。
9. 存在多个候选或用户要求比较时，采用相同条件逐项判断标准。
10. 证据表明某项标准失败时，针对相关输入创建派生候选。证据不完整时，调用对应测量或报告 `unknown`。
11. 应用下文的停止与交接规则。根据新证据或变化后的输入提交有明确目标的修订请求。

## 基于关键帧的生成与修订

对于依赖关键帧级动作的任务：

1. 先检查现有 Clip 和分析结果。缺少可用关键帧数据时，根据任务已明确的语义 Prompt 和受支持的约束生成初始候选，再取得完整 `animation.analysis` 结果。仅在 `generation.get` 的 `post_analysis` 成功完成且包含完整可用关键帧数据时复用；该字段缺失、失败或不完整时，对已完成的 Clip 调用 `animation.analysis`。
2. 将分析返回的关键帧用于观察和选帧。使用 `pose.get` 与分析证据检查相关帧，再通过 Unity `AnimationClip`／`AnimationCurve` API 或其他已验证的项目 API 定位并编辑实际曲线关键帧。保留原 Clip，并创建派生候选。
3. 只修订与已声明的动作、阶段、轨迹、接触或结束状态标准冲突，或有证据表明确属冗余的关键帧。保留维持预期阶段变化、接触和过渡所需的关键帧。记录改动的帧／曲线，以及每项改动所依据的证据。
4. 每次生成或编辑关键帧后，都使用相同标准和可比的分析设置评估候选，并与紧邻的上一个候选及当前最佳候选比较。保留满足硬性要求的最佳候选。如果新候选未按已声明的目标标准优于紧邻的上一个候选，则拒绝该分支、保留当前最佳候选，并停止这轮修订。

## Clip 过渡约束

每个相邻动画 Clip 过渡，都使用 `animation.generate` 的 `inout` 约束显式表达，并为相关 In／Out 边界指定已完成的源 Clip。检查生成结果中的 `inout_sampling`，并评估组装后 Timeline 的衔接处。

过渡时间很短时，增加 In／Out 的 `window_frames`；有帮助时也增加 `sample_count`，以提供更宽的边界上下文。窗口长度受源 Clip 可用帧数和生成时长限制，采样数必须适配不同的模型帧。`outside` 会先补入上下文再裁切，并保持请求的输出时长；`inside` 则约束返回 Clip 自身的起止窗口。根据可用源帧范围和返回的 `inout_sampling` 判断上下文是否足以验证过渡。

## Prompt 表述

将动作、阶段、路径/方向、速度、身体状态、对象/接触和预期结束状态组成简洁的自然语言 Prompt。数据集式标签常用 `walk_ff_225_stop`、`jog_arc_cw_loop`、`two_hands_walk_ff_start` 这样的 token。

## 识别约定

识别用于根据证据检验任务意图。需要区分动作语义时，使用调用方给出的备选项；未提供时，根据 Prompt 和验收标准构造相关备选项。文件名、Clip 名称、候选顺序和 ID 用于来源定位，视觉显著程度用于图像观察，不作为动作语义依据。

只执行以下集合中与任务相关的识别项：

```text
visual: trajectory_shape, action_semantics, visual_motion_quality, contact_pattern
structured: loop_endpoint, keyframe_heading, trajectory_turn,
            trajectory_length, phase_track, endpoint_pose, motion_profile,
            force_line
```

视觉结果刻意限制为较小的取值集合：

```text
trajectory_shape: closed_loop | open_path | near_static | unclear
visual_motion_quality: smooth_appearance | visible_break | unclear
contact_pattern: alternating | left_dominant | right_dominant | unclear
```

每个识别项都返回取值、置信度和证据。按标准需要检查结构化字段、可读图像，以及播放或时序测量；现有证据缺失、不可读或冲突时，标记 `unknown` 或 `unclear`。`smooth_appearance` 描述静态图形，播放流畅度使用时序证据。结构化轨迹值读取命令返回的具名字段。

对于 `force_line`，读取 `clip.motion_profile.force_line`。比较整段 Clip 以及各 `phase_track` 区间内左右肩到手矢量的矢状面角度变化总和。`imbalance_ratio` 定义为 `abs(left-right) / max(left,right)`；只有结果状态为 `ok` 且比例不超过 `0.15` 时，才将 `balanced` 视为通过。状态为 `insufficient_evidence` 时将该项标记为 `unknown`。这是对手臂摆动对称性的采样指标，不是物理力的估算。

比较动作语义时，使用用户给出或从 Prompt 推导的备选项，以及阶段／姿态／接触证据。检查多个相关帧中的阶段覆盖，并结合上下文理解单个接触或锚点帧。证据无法区分备选项时，报告 `unknown`。

## 比较约定

对每个候选分别分析和渲染，使用相同的图像请求、分辨率和证据流程。比较前核对候选与图像的对应关系。只比较任务已声明的标准，例如语义正确性、轨迹连贯性、足部接触、必要阶段覆盖、必要 Pose 覆盖、表现力度、端点连续性，或已声明的相邻 Clip 过渡。

每项标准报告 `candidate_1`、`candidate_2`、`tie` 或 `unknown`，并附简短理由和证据。按声明的目标及对应证据逐项比较；差异明确时优先选择相应候选，否则报告持平或证据不足。

## 证据边界

每项验收结论都应保留简洁的来源记录：

```text
被评估的候选／源资产，以及提供时的 request／animation／analysis ID
项目、场景、Session、目标 Timeline 及其 Clip／轨道绑定
采样帧或区间、帧基准、分析／渲染设置
相关角色／道具的 Transform、偏移和源资产状态
返回的证据路径或测量字段、标准结果及限制
```

使用已有 ID 和 Session 历史定位证据。工具未返回 ID 时，引用实际资产、帧和证据路径。复用证据前，确认被评估来源及相关场景／Timeline 状态仍然一致。未发生变化的依赖项可以复用证据；角色 Clip 变化后，重新检查依赖它的道具跟随采样；绑定、偏移或道具状态变化后，重新检查受影响的交互证据。集成后确认每张图像对应正确候选、Timeline 和相机取景。

分别报告以下证据：

- **视觉**：已打开图像中实际可见的内容。
- **结构化**：命令返回的实测字段。
- **播放**：实际播放或受支持的运行时检查中观察到的内容。

使用静态图片判断可见姿势和构图；使用受支持的时序测量或实际播放检查速度／加速度平滑、滑步、跳变和连续性。说明数值测量的采样范围，并区分它与完整播放观察。证据缺失时标记为 `unknown`，不等于失败。区间结论使用多帧测量；单帧关节距离描述该采样点的关系。

选择修订方式前，先归因：根据结构化错误修正无效引用、前置条件或请求字段；角色 Clip 已完成但不满足标准时调整生成输入；道具运动、绑定、偏移或同步错误时检查集成；观察缺失、过期或不足以得出结论时调用相关分析、采样或播放检查。多种类别可以同时存在。

## 修订与人工交接

内部使用针对性修订表：

```text
失败标准 → 支持证据 → 修改的输入 → 新候选 → 结果
```

进入生成／修订循环前，记录用户指定的候选数量／时间预算和停止条件。即使用户未另行指定预算，也遵循用户给出的停止条件；用户指定的预算作为尝试上限。只有用户既未指定预算，也未给出停止条件时，才使用本地成本控制默认值：一个初始候选，以及针对同一失败标准最多两次定向修订。记录尝试次数和共用候选；在已有授权范围内继续，并报告成本／耗时提示。标准名称或循环标签变化时，沿用累计尝试记录。

用户提供停止条件时，按其条件执行；若必要操作无法通过可用路径完成，或剩余决策需要人类艺术判断，则提前停止。用户未提供停止条件时，在必要标准通过，或可比证据下连续两次定向尝试没有实质改进时停止。用户提供的候选／时间预算作为循环上限；只有用户既未提供预算，也未给出停止条件时才使用本地默认预算。根据已声明的标准定义改进；更换 Seed 或收到 `completed` 不是改进证据。缺少证据时先补充检查，再决定是否生成。

保留满足硬性要求的最佳候选，拒绝使先前已通过要求退步的结果。如果没有候选满足硬性要求，保留最佳部分产物，并报告其失败／未知项。将修订聚焦在受影响的输出，并重新检查其依赖项。缺少某条命令本身不是停止条件：先在用户的工具限制内检查相关包和 API 路径，再报告工具限制。如果无法取得必要工具，停止依赖该工具的执行，报告问题，并等待用户修复，不得改用 subagent 代替。

简单道具在已有能力范围内使用 Kimodo 命令，必要时使用 Unity API 制作 Transform 曲线、Timeline 轨道或手部挂接。通过共用接触帧、偏移、Timeline 范围和证据 ID，使道具始终与角色候选对应。同时验证角色姿态和对象运动；API 路径确实不可用时，将对应标准标为 unknown，并说明限制。

## 结果报告

明确选定的 Clip／资产及目标 Timeline。将必要标准逐项报告为 `verified`、`failed` 或 `unknown`，每项附上对应证据和相关限制。区分请求被接受、任务进入最终状态、角色 Clip 验收通过，以及完整交互验收通过。必要项仍为 unknown 时，不得声称已经完成完整验证。

概述针对性尝试、最佳结果、失败类别，以及实际停止原因。仍有剩余工作时，明确受影响的区间、身体部位、曲线、绑定或缺失证据，并给出具体下一步。工具链修复或证据缺口不一定需要交接给动画师；只有确实需要动画师的工作才做此类交接。

遇到相关症状时，查阅 [`known-issues.md`](known-issues.md) 中的观察结果和可选绕行方法。当前工作流以本文为准；归档手册可用于了解历史背景。
